# M4.5 — UI/UX refinement (Content Studio)

**Status:** implemented, awaiting review (2026-11-19).
**Reference:** `docs/design/content-studio-ui-prototype.html` (visual and interaction source).
**Scope:** `apps/web` only. No API, schema, worker or domain changes.

## 1. What changed

The web app takes the prototype's design system (tokens, typography, cards, pills, tables,
stepper, tabs, modals, toasts, breakpoints at 1100 px and 760 px) and its information
architecture: a dark sidebar with Workspace / Production / Settings groups and a topbar with a
breadcrumb and search. Dark mode keeps working through a second token set.

| Prototype page      | Route                        | Data (all real, from the existing API)                                                      |
| ------------------- | ---------------------------- | ------------------------------------------------------------------------------------------- |
| Overview            | `/`                          | Counts, weekly creation chart, stage counts, recently updated (projects + content lists)    |
| Projects            | `/projects`                  | Cards with content / in-production / channel counts; search; archived filter; create        |
| Content library     | `/content`, `/projects/[id]` | Filters (search, status group, platform, project) in the URL; snapshot; recent activity     |
| Production pipeline | `/pipeline`                  | Board by stage (draft → script → storyboard → images → approved) plus "needs attention"     |
| Content workspace   | `/content/[id]`              | Stepper, tabs (script & brief / storyboard / keyframes / activity), checklist, cost, models |
| Content masters     | `/masters`, `/masters/[id]`  | Featured (latest) master, list, variants, create master, edit master brief, add variant     |
| Asset library       | `/assets`                    | Type / project / name filters, grid, upload, lineage (asset, job, ancestors, usages)        |
| Settings            | `/settings`                  | Account, project profile (owners edit), live dependency status                              |

Sign-in now lands on the Overview (`/`). `/login` and the public `/status` page stay outside the
shell. Existing URLs are unchanged (Next.js route group `(studio)`).

## 2. Prototype elements not reproduced (no real data or API)

Per the brief "no mock data, fake metrics or non-functional controls":

- **Monthly usage / AI spend / soft limit** (sidebar, overview): there is no workspace usage or
  budget endpoint yet (budgets are M7). Replaced by a Projects stat.
- **Trend percentages** ("↑ 18% vs. last month"): no historical aggregates. Stat footers show
  real counts instead (created in the last 30 days, waiting for review, owned projects).
- **Notifications, help, export report, "More actions"** buttons: no backing feature.
- **Workspace switcher**: there is no workspace entity; the block shows the caller's project
  counts without a switch control.
- **Content IDs ("CF-024")**: not part of the data model; rows show platform and language.
- **Per-block "Edit" buttons** on the script: one "Edit script" dialog edits all fields (the
  existing PATCH creates a new version).
- **"Request changes"**: maps to the existing **Reject** action (no separate state exists).

## 3. Decisions

- **Workspace-wide views without new endpoints.** The API is project-scoped, so `lib/workspace.ts`
  reads each project's lists and follows cursors (up to 10 pages of 100 per list; a notice
  appears if truncated). Fine for the MVP; a workspace summary endpoint would replace it at scale.
- **Cost on the content workspace** shows the _latest_ script, storyboard and per-scene image
  jobs (`GET /generation-jobs/:id`, scene `lastJob`). It is labelled as such: earlier runs and
  regenerations are not included because no "cost per content item" endpoint exists. Reported,
  estimated and unknown cost stay separate; unknown cost is never shown as $0 (ADR-0012).
  Money is summed as exact decimals (`lib/money.ts`).
- **Tabs keep every panel mounted** (hidden when inactive) so open editors and job polling
  survive tab switches; the active tab is mirrored in the URL hash (`#storyboard`). The default
  tab follows the first open gate.
- **Status labels** are human-readable ("Script review") through one mapping
  (`lib/content-status.ts`), which also defines stages, review states and filter groups.
- **Fonts** (DM Sans, Manrope) are self-hosted at build time by `next/font`: the browser never
  calls Google. Building the web app therefore needs network access to Google Fonts.
- **Dialogs** use the native `<dialog>` (focus trap, Escape, inert background) and render their
  form only while open.

## 4. Verification

- `pnpm check` (format, lint, typecheck, unit tests incl. `apps/web/src/lib/web-helpers.test.ts`,
  build).
- Playwright (`pnpm test:e2e`, 11 tests): the existing auth, masters/upload and
  script → storyboard → images → keyframes flows adapted to tabs and dialogs, plus
  `e2e/studio.spec.ts` (overview, ⌘K search, URL filters, pipeline board, masters list, asset
  lineage of uploaded and generated images, project settings, project creation).
- Checked at 1440 px (light and dark) and 390 px: no horizontal page scroll on any page.

## 5. Known limitations / follow-ups

- No character / environment pages yet (attaching a reference to a character remains an API step).
- Workspace aggregation is N+1 over projects; add a summary endpoint if project counts grow.
- Content cost covers latest jobs only until a per-content cost endpoint exists (M7 cost work).
- The paid image benchmark (M4 G2) is still pending an OpenRouter key.
